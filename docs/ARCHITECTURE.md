# Архитектура портала «Учусь.РФ»

**Вариант:** № 5, 09.02.07, демонстрационный экзамен 2026. Обе части задания выполнены как единый проект.

## Технологический стек

- **Front-end:** HTML5, CSS3 (CSS Grid, Flexbox, адаптивные media queries), нативный JavaScript ES Modules (классы, функции, асинхронные запросы Fetch API, обработка форм), SVG-графика.
- **Back-end:** Node.js 22.13+ (встроенный HTTP-сервер `node:http`), JSON REST API, модульная серверная логика.
- **База данных:** SQLite через встроенный в Node.js модуль `node:sqlite` (без установки нативного `sqlite3`). Схема — `database/schema.sql`; файл базы создаётся при первом запуске.
- **Контроль версий:** Git с промежуточными коммитами и понятными описаниями.
- **Проверка:** автоматические интеграционные тесты `node --test`.

В проекте **нет необходимости устанавливать npm-пакеты**. Для экзамена это сокращает время запуска, устраняет зависимость от интернет-соединения и ошибок нативных модулей. Внешние веб-шрифты опциональны: без них используется системный шрифт. UI использует собственную библиотеку CSS-компонентов (кнопки, карточки, формы, таблицы, badges, модальные окна, сетки).

## Связи таблиц

Поле `id` — первичный ключ, `*_id` — внешний ключ, UQ — уникальность.

- `users 1:N applications` — пользователь может создать много заявок.
- `courses 1:N applications` — на один курс записываются многие люди; один курс можно проходить неоднократно, поскольку уникального ограничения на пару пользователь/курс нет.
- `applications 1:0..1 reviews` — для завершённой заявки можно оставить один отзыв.
- `users 1:N reviews` — отзывы принадлежат пользователям.
- `users 1:N sessions` — авторизованные сеансы.
- `users 1:N status_history` — администратор меняет статусы заявок.
- `applications 1:N status_history` — история каждого изменения статуса.

Схему можно посмотреть в `docs/ER_diagram.svg` (векторное изображение) или `docs/ER_diagram.mmd` (Mermaid), исходный SQL: `database/schema.sql`.

## Валидация

- Логин уникальный, от 6 символов, только латинские буквы и цифры, обе группы обязательны.
- Пароль пользователя от 8 символов (пароль `Demo20` заранее созданного админа задан экзаменационным условием).
- Проверка ФИО (минимум два слова), телефона (не менее 10 цифр) и email.
- Дата `ДД.ММ.ГГГГ` должна существовать и не быть прошедшей.
- Способ оплаты только из фиксированного списка.
- Отзыв (оценка 1–5 и текст 10–1000 символов) доступен только владельцу заявки после статуса «Обучение завершено».
- Пользователь не может получить чужие заявки; права админа проверяются на сервере, а не только в интерфейсе.

## Безопасность

Пароли не записываются открытым текстом: используются `scrypt` + случайная соль, сверка через `timingSafeEqual`. Сессии хранятся сервером: в cookies только случайный токен (`HttpOnly`, `SameSite=Lax`, 7 дней), в БД его SHA-256. SQL-запросы параметризованы; пользовательский текст в DOM экранируется. Для изменяющих запросов проверяется `Origin`, если браузер передал его. Для продакшена дополнительно требуются HTTPS, rate limiting, секреты окружения и профильное тестирование безопасности.

## Проектные решения

- Приложение многократно использует UI-компоненты из `public/js/api.js` (карточки, статусы, иконки, форматы дат).
- Слайдер реализован классом `AccessibleSlider` и поддерживает 4 разных локальных SVG, автоматическое переключение каждые 3 секунды, стрелки, точки навигации, свайпы, паузу при взаимодействии и `prefers-reduced-motion`.
- Адаптивность: контрольный экран 390×844, сетки перестраиваются на ширине 720px и 400px.
- Веб-страницы являются отдельными HTML-файлами; дизайн-макеты также включены в `static-mockups/`.
