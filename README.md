# Учусь.РФ — готовый проект для демонстрационного экзамена (Вариант № 5)

**Специальность:** 09.02.07 «Информационные системы и программирование»  
**Квалификация:** Разработчик веб и мультимедийных приложений  
**Модуль 1:** Проектирование и разработка информационных систем  
**Модуль 2:** Разработка дизайна веб-приложений

Функциональный портал онлайн-курсов **«Учусь.РФ»** со своей базой данных, интерфейсом пользователя и защищённой панелью администратора. Это самостоятельная реализация **варианта № 5**: архив-пример `demo-main.zip` относился к бронированию помещений и не подходил по предметной области. В приложенных материалах также присутствует страница варианта № 4 — в этом проекте она не используется.

## 1. Запуск проекта (Windows)

**Понадобится Node.js версии 22.13 или новее**: https://nodejs.org/ (рекомендуется последняя LTS-версия).

1. Распакуйте ZIP-архив целиком в отдельную папку, например на рабочий стол.
2. Откройте папку `uchus-rf-variant5`.
3. **Дважды щёлкните `START.bat`** (или откройте терминал в папке и выполните `npm start`).
4. Дождитесь строки `Учусь.РФ запущен: http://localhost:3000`.
5. Откройте в браузере **http://localhost:3000**.

**Никаких `npm install`, `seed.js`, `.env`, настройки MySQL и регистрации в сторонних сервисах не требуется.** Все данные и служебные таблицы SQLite создаются автоматически при первом запуске. Сервер должен оставаться запущенным, пока вы работаете с сайтом. Для завершения: `Ctrl+C`.

Если порт 3000 занят, в Windows PowerShell можно написать:

```powershell
$env:PORT=3001
node server.js
```

Тогда адрес будет `http://localhost:3001`.

Для macOS/Linux: `sh START.sh`. Для тестов: `npm test`.

## 2. Готовые аккаунты для демонстрации

| Роль | Логин | Пароль | Что показывает |
| --- | --- | --- | --- |
| **Администратор** | `Admin26` | `Demo20` | Все заявки, фильтры, сортировка, изменение статусов, журнал |
| **Ученик** | `student26` | `Student2026` | Личный кабинет, три заявки разных статусов, отзыв |

Логин/пароль `Admin26`/`Demo20` заданы в экзаменационном задании. Пароль тестового ученика нужен только для демонстрации. Для проверки регистрации можете создать новый аккаунт с собственными тестовыми данными.

## 3. Реализованные возможности

### Модуль 1 — проектирование и разработка

- Настоящая реляционная база SQLite с шестью таблицами и внешними ключами: пользователи, курсы, заявки, отзывы, сеансы и история статусов.
- ER-диаграмма и SQL-схема, индексы и ограничения целостности.
- Регистрация с проверкой логина (латиница + цифры, от 6 символов, уникальность), пароля (от 8 символов), ФИО, телефона и email.
- Авторизация по логину/паролю и сохранение сессии в безопасной cookie.
- Запись на выбранный курс, дата начала в формате `ДД.ММ.ГГГГ`, один из трёх способов оплаты, автоматический статус «Новая».
- Личный кабинет показывает заявки только владельца.
- Отзыв с рейтингом от 1 до 5 после завершения обучения, по одной оценке на заявку.
- Админ-панель: все заявки, фильтрация по статусу и курсу, поиск по имени/логину/курсу, сортировка и смена статуса с подтверждением.
- История изменений статуса и статистика.
- Серверная проверка прав: чужие заявки и админ-методы недоступны обычному пользователю.

### Модуль 2 — дизайн

- Индивидуальный современный дизайн, одинаковый для всех страниц.
- Отдельные страницы регистрации, авторизации, каталога, личного кабинета, подачи заявки и администрирования.
- Полностью адаптивная мобильная версия для **390 × 844 px**: формы, карточки, мобильная навигация и таблица с горизонтальной прокруткой.
- В личном кабинете слайдер из **4 локальных SVG-изображений**, **автопереключение раз в 3 секунды**, стрелки назад/вперёд, точки навигации и поддержка свайпов.
- Подсказки при валидации, сообщения об ошибках и успехе, модальные окна, поиск и сортировка.
- Оптимизированные векторные иллюстрации. Шрифты имеют системный fallback; основные функции не требуют интернета.
- Автономные HTML-макеты в `static-mockups/`, а также изображения экранов 390×844 и 1440×900 в `docs/previews/`.

## 4. Структура файлов

```text
uchus-rf-variant5/
├── START.bat                ← запуск в Windows (двойной клик)
├── START.sh                 ← запуск в Linux/macOS
├── README.md                ← этот файл
├── package.json             ← npm start / npm test (зависимостей нет)
├── server.js                ← HTTP-сервер, REST API, защита доступа
├── db.js                    ← SQLite, тестовые данные, хеширование паролей
├── database/
│   └── schema.sql           ← шесть таблиц с ключами и индексами
├── public/                  ← работающий веб-сайт
│   ├── index.html           ← каталог и главная
│   ├── register.html        ← регистрация
│   ├── login.html           ← авторизация
│   ├── dashboard.html       ← личный кабинет
│   ├── apply.html           ← оформление заявки
│   ├── admin.html           ← администратор
│   ├── css/styles.css       ← UI-компоненты и адаптивный дизайн
│   ├── js/                  ← модули и логика страниц
│   └── assets/              ← оптимизированные SVG-иллюстрации, слайдер
├── static-mockups/          ← отдельные готовые макеты (.html)
├── docs/
│   ├── ER_diagram.svg       ← ER-диаграмма в векторе
│   ├── ER_diagram.png       ← ER-диаграмма в PNG
│   ├── ER_diagram.mmd       ← редактируемый Mermaid
│   ├── ARCHITECTURE.md      ← стек, БД, API, безопасность
│   ├── TEST_SCENARIOS.md   ← критерии и сценарий защиты
│   └── previews/            ← снимки экрана, включая мобильные 390×844
└── tests/portal.test.cjs    ← 6 интеграционных автотестов
```

**Важно:** файл `database/portal.sqlite` создаётся сам и намеренно не включён в Git. Чтобы полностью сбросить тестовую базу к исходному состоянию, остановите сервер и удалите `database/portal.sqlite` (а также возможные `portal.sqlite-wal` и `portal.sqlite-shm`). При следующем старте данные создадутся заново.

## 5. Быстрый сценарий показа преподавателю

1. На главной откройте раздел курсов. Покажите шесть программ и фильтры направлений.
2. Зарегистрируйте нового ученика и покажите валидацию полей.
3. Войдите под ним, отправьте заявку на курс с датой, например `25.12.2027` и способом оплаты «СБП».
4. В кабинете покажите статус **«Новая»** и слайдер из четырёх изображений. Подождите три секунды, нажмите стрелки.
5. Выйдите, войдите под `Admin26`/`Demo20`. Найдите заявку, переведите в статус **«Идет обучение»**, затем **«Обучение завершено»**. Продемонстрируйте фильтр, сортировку и журнал.
6. Снова войдите под учеником и оставьте отзыв о завершённой программе. Покажите отзыв в истории и на главной.
7. Нажмите `F12`, включите режим мобильного телефона и установите разрешение **390 × 844**. Откройте разные страницы, покажите меню и формы.
8. В терминале запустите **`npm test`**: все 6 сценариев должны завершиться успешно.
9. Откройте файл `docs/ER_diagram.svg`, расскажите о первичных и внешних ключах.
10. В терминале выполните `git log --oneline`, покажите историю промежуточных коммитов.

## 6. Контроль версий

История Git включена в архив (`.git`). Коммиты фиксируют отдельные этапы: структура базы, интерфейс, проверки API, ER-диаграмма, адаптивные макеты, документация. После распаковки проверьте:

```bash
git log --oneline
```

Если Git не установлен, его можно скачать с https://git-scm.com/; на работоспособность сайта это не влияет.

## 7. Замечания

- Оплата **не списывается**: согласно заданию сохраняется только выбранный **способ оплаты**.
- Это готовый учебный проект для локальной демонстрации, а не публичный коммерческий сервис. При публикации в интернете нужны HTTPS, централизованное логирование, резервное копирование, ограничение частоты запросов и дополнительное тестирование.
- Исходное задание требует ER-диаграмму по предметной области портала. На присланных фото в конце виден **вариант № 4** со схемой `Customer/Trainer/Product/Course`; эта схема не относится к варианту № 5 и намеренно заменена корректной.
- Дизайн-макеты в `static-mockups/` можно открывать без сервера для показа оформления. Для сохранения данных и работы кнопок используйте сайт через `START.bat`.
